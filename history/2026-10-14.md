## #144 — docs/ARCHITECTURE.md's HIAE Protocol version banner had no in-repo guard

Filed after the 21st run's "no non-gated work remains" conclusion, from a
fresh sweep for the next unguarded current-state claim (the #129-#139 class).

### The gap (verified before filing)

- `docs/ARCHITECTURE.md:3` carries `**HIAE Protocol Version**: v5.39.1`,
  which must equal the hub-synced `AGENTS.md:38` `(HIAE Protocol v5.39.1)`.
- `grep -n HIAE skills/architecture-360-audit/sentinel.sh` -> zero matches;
  `grep -rn HIAE tests/` -> zero matches. No HIAE check anywhere in-repo.
- The only live gate is hub-side and manual:
  `python3 ~/sandbox/hyer/scripts/check_version_banners.py .` -> `PASS:
  docs/ARCHITECTURE.md HIAE Protocol version banner(s) match AGENTS.md.`
  Its PASS transcript is captured at `profile.md:501-504`, but nothing re-runs
  it; CI runs only the five bash suites + pytest.
- Second-order: the hub checker skips an *absent* banner
  (`file_version is not None and file_version != agents_version`), so
  deleting the banner line silently disables its own gate (#98 class: an
  absent check is not a passing one).

### The fix

Sentinel gains a section comparing the HIAE banner regex (same shape as the
hub checker's `_HIAE_BANNER_RE`, applied to whitespace-unwrapped text) across
`AGENTS.md` and `docs/ARCHITECTURE.md`:

- either banner absent -> failure (`AGENTS.md carries no HIAE Protocol
  version banner` / `docs/ARCHITECTURE.md carries no HIAE Protocol version
  banner`);
- versions disagree -> failure (`docs/ARCHITECTURE.md banner says vX, AGENTS.md
  says vY`);
- both present and equal -> `[ OK ] HIAE banner: docs/ARCHITECTURE.md matches
  AGENTS.md (v5.39.1)`.

No inline `current (vX.Y.Z` phrases exist in this repo (the hub checker's
other scan), so only the banner comparison was needed.

### Proven red first

Case [43], four probes: banner corrupted to `v9.9.9`, banner line deleted,
AGENTS.md banner deleted, unmutated control. Before the guard existed:
7 failures (coverage exited 0 on all three drifts; control had no OK line).

Two test bugs surfaced while turning RED green — both were bugs in the new
test, not the guard:

1. Probe C's removal regex required a literal leading space (` \(HIAE`), but
   `AGENTS.md:38` begins the line with `(` (newline before it), so the removal
   silently matched nothing (`sys.exit` fired, the test script continued under
   `set -uo pipefail` without `-e`, and coverage stayed green on an unmodified
   file). Fixed to `\(HIAE Protocol v[\d.]+\)`.
2. The control's OK-line grep allowed only one version dot
   (`\(v[0-9]+\.[0-9]+\)`) but the live banner is `v5.39.1` (two dots), so the
   control failed even though `$OUT` contained the exact line (confirmed by
   the fail branch's own printf). Fixed to
   `\(v[0-9]+\.[0-9]+(\.[0-9]+)?\)`.

## #145 — docs/SECURITY.md's file-permission claims had no in-repo guard (+ closing section 24's test debt)

Filed from the same sweep as #144 (the #129-#145 unguarded-current-state
class), after re-verifying that the previous run's sentinel section 24 (the
ARCHITECTURE.md/OPERATOR_MANUAL.md timeout-claim guard) had shipped with no
issue number and no probes in `tests/test_sentinel.sh`.

### The gap

- `docs/SECURITY.md:22-27` ("File Permissions Architecture") states six
  path->mode pairs: `~/.sec/` 0700, `~/.sec/sec.conf` 0600,
  `~/.cache/bitwarden/` 0700, `.../session` 0600, `.../snapshot_*.json` 0600,
  `.../migration_transaction.json` 0600.
- Nothing re-verified them: `grep -n SECURITY.md sentinel.sh` found it only as
  a manifest/citation target, never a claim guard. A dropped `chmod` or a mode
  change would leave the security doc lying with CI green.
- All six map to live `chmod` calls: `bin/sec:11` `chmod 700 "$CONFIG_DIR"`
  (`CONFIG_DIR="$HOME/.sec"`), `bin/sec:36` `chmod 600 "$CONFIG_FILE"`,
  `bin/bw-session-keeper:14` `chmod 700 "$CACHE_DIR"` and
  `:38` `chmod 600 "$SESSION_FILE"`, `bin/sec-organizer:217`
  `chmod 600 "$snapshot_file" "$PLAN_FILE"`, `bin/sec-migrator:170`
  `chmod 600 "$TX_FILE"`.

### The fix

Sentinel section 25 parses the SECURITY.md block, resolves each documented
path from the variable it is assigned to (a small `_security_env` built from
every `VAR="..."` assignment across the four bin files, with `$VAR`/`${VAR}`
expanded iteratively and any unresolved `$(...)`/`${...}` compared as a `*`
glob), and checks four ways:

- the doc's stated mode agrees with its own inline `chmod` (`0600` vs `chmod 600`);
- the doc path matches the live assignment (glob-aware, so `snapshot_*.json`
  matches `snapshot_$(date ...).json`);
- the live `chmod` on that variable agrees with the documented mode;
- every guarded path is still documented (reverse direction).

Section 24's untested debt is closed by case [44]; section 25 by case [45].

### Proven red first

- Case [44], four probes: ARCHITECTURE.md default -> 99s, OPERATOR_MANUAL.md
  default -> 30s, controller `BACKEND_TIMEOUT` -> 30, unmutated control.
- Case [45], four probes: doc mode vs its own chmod, doc mode vs the live
  chmod, session line dropped, live chmod 600 -> 644, unmutated control.

Both were red before the guards (coverage exited 0 on the drifts and the
controls had no OK line), green after.
