## #139 - profile.md's bin Python-controller count had no drift control

`sentinel.sh coverage` checks both halves of profile.md's bin/ component
decomposition (`sentinel.sh:889-914`): the `(\w+) sibling executables` number
and the `(\w+) Python controller` number, the latter against
`_live_controllers = [h for h in bin_helpers if h.endswith("-controller.py")]`.
The suite's case `[38]` seeded one workdir for that decomposition, corrupted
only the sibling-executables half, and asserted only that message. Nothing in
`tests/test_sentinel.sh` mentioned "Python controller" at all, so the second
branch could have been dead - a regex that stopped matching, a `_NUM_WORDS` key
that went missing, a `-controller.py` suffix rule that broke - and the suite
would still have been green.

Fix, in case `[38]`:

- `WRONG_CONTROLLERS="$(num_word one)"` next to the existing `WRONG_*` block.
  Derived like every other one: `num_word` returns the first numeral word
  differing case-insensitively from the live spelling, so the control can never
  collide with the live value.
- A fourth seeded workdir `$WORK_S8D`, added to the existing `for W in ...; do
  seed "$W"; done` loop.
- A corruption that rewrites ONLY the controller half:

  ```python
  s2, n = re.subn(r"(\b[\w-]+ sibling executables, )[\w-]+( Python controller)",
                  r"\g<1>%s\g<2>" % wrong, s, count=1)
  ```

  The sibling-executable half is captured into group 1 and re-emitted
  unchanged, so only the controller message can fire and the assertion below is
  unambiguous. `\g<1>` rather than `\1` because a bare `\1` followed by a digit
  would be read as a group number. `[\w-]+` rather than a literal so a
  capitalized or hyphenated live spelling still matches; `count=1` and the
  `n != 1` exit keep the control honest if the shape ever changes.
- Two assertions: coverage exits nonzero, and coverage names
  `component decomposition says N Python controller(s), live tree has M`.

Mirror churn: the live assertion count is a static count of lines matching
`\s*(ok|no) ` in `tests/test_sentinel.sh` (`sentinel.sh:1290-1293`), so two new
branches are +4, not +2. RESUME.md and HISTORY.md both moved 430 -> 434.

Negative control: forcing `WRONG_CONTROLLERS="one"` - the live spelling, so the
corruption becomes a no-op - produced exactly two failures, `coverage accepted a
drifted bin Python-controller count` and `coverage did not name the drifted bin
Python-controller count`, and touched no other case. That is the evidence the
control was live rather than decorative.

RESUME.md's new 15th-run paragraph added 13 lines, so its nine self-anchors
shifted +13 via the per-line "current file" token walk. The walk's regex

### 2026-10-13 — #126: bin/sec's `get_cfg_val` no longer silently drops a `sec.conf` line with no `=`
- **Trigger**: #126, the last open silent-drop arm and the one the tracker had
  marked "not autonomously actionable without a design decision". `bin/sec` is
  the sole `sec.conf` owner; its `get_cfg_val` awk had `in_s { eq=index($0,"=");
  if (eq==0) next; ... }`, so a typo'd line like `default_backend bitwarden`
  (no `=`) was skipped with no signal: a silent drop in a credential-adjacent
  config parser, the highest-severity class left in the repo.
- **Design call (cheapest reasonable path, per the standing order that forbids
  parking)**: warn, not reject. Exit code and parse result are UNCHANGED, so no
  existing consumer can break; the arm now prints a tagged
  `[WARN] sec.conf: ignoring malformed line <NR> (no =): <text>` to stderr,
  matching AGENTS.md §8's one-`[ TAG ]`-line-per-event rule. The `eq==0` branch
  lives inside the `in_s` match, so a malformed line warns only when its section
  is queried (`default_backend` always; `auto_rotate` per-tenant), never
