## Second pass on the drift-control sweep (same run)

The first sweep's audit method was wrong in a way worth recording: it grepped
for corruption replacement strings that *begin* with a numeral word, so a
control whose literal sat later in the string was never examined. Dumping
every `python3 - <<PY` heredoc in `tests/test_sentinel.sh` and grepping the
whole replacement body found six survivors that commit 9a4938e left pinned:
profile.md's "seven sibling dispatchers", ADAPTERS.md's "seven sibling `bin/`
helpers", docs/MULTI_TENANCY.md's "eight fixed aliases", docs/OPERATOR_MANUAL.md's
"four core principles", SKILL.md's "five `tests/*.sh` suites" and "executes all
five bash suites". Each now takes a `WRONG_*` word from the existing `num_word`
helper as argv[2] and each expectation widened from the literal to
`[A-Za-z-]+` / `[0-9]+`.

One live bug surfaced only by running the suite: the scanner-suite expectation
was `grep -qE "... the [A-Za-z-]+ \`tests/\\*\\.sh\` suites ..."` in double
quotes, so bash command-substituted the backticked `tests/*.sh` before grep saw
the pattern -- `tests/*.sh: No such file or directory` on stderr, and the
assertion failed even though sentinel had named the drift correctly. Any grep
whose pattern contains backticks must be single-quoted.

Negative control: forcing the six new `WRONG_*` values onto the live words
(`seven`, `seven`, `eight`, `four`, `five`, `five`) produced 12 failing
assertions, six pairs of "coverage accepted a drifted ..." and "coverage did
not name the drifted ...", proving each control now depends on derivation
rather than on a lucky literal. Restored from a backup afterwards.

## Issue #138: citations only walked the audit skill's two docs

The guard-hardening lane had just finished deriving every live count in
`tests/test_sentinel.sh`. Looking one layer out at the instrument itself:
`citations` builds `claim_sources = {skill, profile}`, so every `file:line`
anchor outside the 360-audit SKILL.md and profile.md was unverified.

Measured with sentinel's own anchor pattern:

    ADAPTERS.md             anchors=0
    RESUME.md               anchors=56
    HISTORY.md              anchors=2
    docs/{ARCHITECTURE,MULTI_TENANCY,OPERATOR_MANUAL,SECURITY}.md  anchors=0

Two of those 58 were genuinely broken, and in the worst possible way:
`RESUME.md` and `HISTORY.md` both cited the audit SKILL.md as a bare
basename at line 451. `resolve()` prefers an exact tracked path, and the repo
has a root `SKILL.md` of 50 lines, so the citation silently bound to the wrong
file -- and 24 tracked files are named `SKILL.md`, so the basename fallback
that `resolve()` offers for unique names can never help here. Both are now
written as `skills/architecture-360-audit/SKILL.md`.

The fix extracts the anchor-resolution block into `anchor_problems()` and
calls it for a second source set -- `ADAPTERS.md`, `RESUME.md`, `HISTORY.md`
and `docs/*.md` -- checking only that the path resolves, that the cited range
sits inside the file, and that no range is reversed. Deliberately NOT extended
to those docs: the bare `line N` rule (RESUME.md's narrative quotes old bare
references while describing a rename, e.g. "urlopen at line 170 -> line 159")
and the stale-content / phantom-claim heuristics (they assume audit-skill
prose density and would fire on narrative docs). `history/*.md` stays excluded
because those archives record now-stale anchors as history, on purpose.

Case [42] drives it with derived values only: the injected out-of-range
anchor is `docs/ARCHITECTURE.md:$((lines + 1))` and the injected reversed range
is `tests/test_dispatch.sh:$lines-$((lines - 1))`, so the control never pins
a live line number. A fifth assertion reads the control copy's OK line and
requires a nonzero "N anchor(s) in the repo docs also resolve" count, which
proves the pass ran rather than vacuously passing on an empty scan.

Second-order: profile.md's §3 claim had to move from "forty-one" to
"forty-two" sentinel cases, and `_NUM_WORDS` had no entry for forty-two, so
the count check silently skipped the word it was given and reported a drift.
The map gained forty-two through forty-five. Mirrors: 41 -> 42 cases,
418 -> 430 assertions, at `ADAPTERS.md:56`/`:262`, `profile.md:22`/`:641`,
RESUME.md and HISTORY.md. HISTORY.md's 2026-10-13 paragraph was rewritten
whole to stay under its 8192-byte budget (8104 bytes), and RESUME.md's twelve
self-anchors were shifted by the 27 lines the new resume paragraph inserted at
the top, including the `` `:158` ``-style shorthands that inherit their file
from the preceding full anchor.

Verified: sentinel 42 cases green, all four other bash suites green,
`sentinel.sh coverage` and `citations` rc=0, pytest 58 passed.
