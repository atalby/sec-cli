### 2026-10-12 — #71: `sec get`/`set`/`unlock` reject an unknown `--flag` at the operand position instead of silently misparsing it as the key/password
- **Trigger**: issue #71 (filed 2026-10-12, held for a go/no-go on backward compatibility). Probes against a fake backend: `sec get --bogus k` reported `Secret '--bogus' not found` (real key `k` silently ignored, exit 1); `sec set --bogus k v` "stored" a secret literally named `--bogus`; `sec unlock --bogus` ran the unlock path with `--bogus` as the password. Decision applied: the loud/honest rejection proposed in the issue — the same behavior #73 already shipped for `bin/sec.ps1` (reject `-`-prefixed operands, tagged, exit 2). Keys/passwords must now not begin with `-` (documented here; a secret literally named `--mykey` was pathological and is now a usage error).
- **Cause**: the `get`, `set`/`create` and `unlock|rotate|keep` arms in `bin/sec` validated *values* of recognized flags (`--scope`, `--type`) but never checked whether the *next operand* was flag-like, so a mistyped flag was consumed as the key/password and the real operand was dropped or ignored.
- **Fix (`bin/sec`)**: a token matching `--*` or `-[a-zA-Z]*` (globs; a bare `-` also matches) at the operand position is now rejected via `usage_error` (tagged `[ERROR]` + `exit 2`) before any backend/auth call —
  - `get`: check after the `--scope` parse, before `key="$1"` (also catches `sec get --scope work --bogus k` and `sec get -x k`);
  - `set|create`: check after the `--type` parse, before `key="$1"` (also catches `sec set --type note --bogus k v` and `sec set -t k v`; the explicit *value* position is untouched, so a value like `-p@ss` is still accepted);
  - `unlock|rotate|keep|setup-keychain`: a pre-exec loop over `"$@"` rejects flag-like args before `bw-session-keeper` is invoked.
- **TDD (`tests/test_dispatch.sh` [2e])**: new section asserts exit 2 + tagged `[ERROR]` for `get --bogus k`, `get --bogus` (no key), `get -x k`, `get --scope work --bogus k`, `set --bogus k v`, `create --bogus k v`, `set --type note --bogus k v`, `set -t k v`, `unlock --bogus`, `rotate --bogus`, `keep --bogus`, `unlock -x`; plus a canary assertion that `get --bogus` exits 2 *before* any `bw` call (bw log byte count unchanged). Suite 68 -> 69 sections; `profile.md` Test-runner count updated (68 -> 69) and the sentinel's suite-count guard re-greened.
- **Verified**: five bash suites ALL TESTS PASSED (dispatch 69 / install 9 / sentinel 10 / sync_guard 16 / write_honesty 11); pytest mirror 29 passed; `sentinel.sh citations` + `sentinel.sh coverage` green.

### 2026-10-12 — #74: `sec get`/`set`/`create` reject trailing operands instead of silently dropping them
- **Trigger**: standing-order sweep after #64 closed (no failing tests, no TODO debt, no unmerged branches, no open PRs; remaining tracker items #51/#67 are non-autonomous). Found the last gap in the silent-misparse class #41/#69/#70/#71/#72/#73 had been sweeping: extra operands after the expected ones were silently dropped, so a typo'd command line still reported success.
- **Observed (probe, fake backend)**: `sec get MY_API_KEY extra` returned the secret (exit 0, `extra` ignored); `sec set MY_KEY val extra` stored `val` (`extra` ignored); same for `create` and `set --type note`.

Both via `usage_error` (tagged `[ERROR]`, exit 2) before any backend/auth call. `run` is unaffected (legitimately variadic: `sec run -- <cmd> [args...]`).

### 2026-10-12 — #75: `sec get --scope` rejects a flag-like folder name
- **Trigger**: last soft spot in the silent-misparse sweep (#41, #69-#74); found while closing #74. The `--scope` value position accepted a flag-like token as the folder name: `sec get --scope --bogus MY_API_KEY` failed loud but misattributed (`scope folder not found: '--bogus'`, exit 1) — the real problem is that `--bogus` was never a folder name. The `sec.ps1` wrapper already rejects `-`-prefixed scope names (#73 fix); `bin/sec` was the laggard.
- **Fix (`bin/sec`)**: after `SCOPE_NAME="$2"`, a name matching `--*` or `-[a-zA-Z]*` is rejected via `usage_error` (tagged `[ERROR]`, exit 2) before any backend call.
